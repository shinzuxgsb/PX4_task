# 网口雷达 → 串口雷达 改造记录

日期：2026-10-09
平台：Orange Pi 5 Max（RK3588，Ubuntu 22.04 / ROS 2 Humble），工作区 `~/px4_ws`

## 1. 改了什么

| | 改造前 | 改造后 |
| --- | --- | --- |
| 雷达 | 蓝海光电 **LDS-50C-E**（网口 / UDP） | 蓝海光电 **LDS-50C-R**（串口） |
| 连接 | 网口，雷达 `192.168.158.98:6543`，本机监听 UDP `6668` | 香橙派 **UART4** → `/dev/ttyS4`，921600 8N1 |
| 驱动参数 | `params/udp_lidar.yaml` | `params/uart_lidar.yaml` |
| 启动 | `run.sh` 里 `LIDAR_PARAMS` 指向 udp 版 | 指向 uart 版（`run.sh` 已改，可用环境变量覆盖） |
| 设备树 | — | 追加 overlay `rk3588-uart4-m2.dtbo` 打开 UART4 |

`/scan` 的话题名、frame_id（`laser_link`）、频率（15Hz，`rpm: 900`）都不变，
所以上游 `carto_pkg` / `slam_pkg` / `px4_ev_bridge` **一行都不用改**。

## 2. UART4 硬件对应关系

香橙派 5 Max 的 40pin 排针，UART4 走 **UART4_M2** 这组 pinmux：

| 排针 | GPIO | 功能 | 接到雷达 |
| --- | --- | --- | --- |
| 19 | GPIO1_B2 | UART4_M2_TX | 雷达 RX |
| 23 | GPIO1_B3 | UART4_M2_RX | 雷达 TX |
| 6/9/14/20/25/30/34/39 任一 | — | GND | 雷达 GND |

> 排针 19/23 在默认状态下是 SPI0 的 TXD/CLK，加载 uart4-m2 overlay 后会切换成 UART。
> 该 mux 引脚与 `/dev/ttyS1`(排针27/28)、`ttyS3`(排针31/33)、`ttyS6`(排针11/13)、
> `ttyS7`(蓝牙) 都不冲突。
>
> 如果实际接线用的是 UART4 的 **m0**(GPIO1_D2/D3) 或 **m1**(GPIO3_D0/D1) 引脚，
> 需要把 overlay 换成对应的那组；注意厂家只提供了 `uart4-m0` / `uart4-m2` 两个 dtbo，
> m1 需要用 m1 自己压一个 overlay。

设备树里的对应：`serial4 = /serial@feb70000`，默认 `status="disabled"`，
这就是改造前 `/dev/ttyS4` 不存在的原因。

## 3. 启用 ttyS4（系统层，一次性）

本机用 u-boot-menu / extlinux 引导，overlay 列表在 `/etc/default/u-boot`：

```bash
sudo bash tools/enable_ttyS4.sh --reboot
```

脚本做的事：

1. 备份 `/etc/default/u-boot` → `/etc/default/u-boot.bak-ttyS4`
2. 在 `U_BOOT_FDT_OVERLAYS="…"` 末尾追加
   `device-tree/rockchip/overlay/rk3588-uart4-m2.dtbo`
3. `u-boot-update` 重新生成 `/boot/extlinux/extlinux.conf`
4. 重启

重启后验证：

```bash
ls -l /dev/ttyS4            # 应出现 crw-rw---- root dialout
dmesg | grep feb70000       # 应有 "ttyS4 at MMIO 0xfeb70000"
```

手动等价操作（不想用脚本时）：

```bash
sudo cp -a /etc/default/u-boot /etc/default/u-boot.bak
sudo sed -i 's#^U_BOOT_FDT_OVERLAYS="\(.*\)"#U_BOOT_FDT_OVERLAYS="\1 device-tree/rockchip/overlay/rk3588-uart4-m2.dtbo"#' /etc/default/u-boot
sudo u-boot-update
sudo reboot
```

## 4. 起雷达并验证

```bash
cd ~/px4_ws
bash run.sh lidar          # 自带 25s 握手等待，然后打 /scan 频率
ros2 topic hz /scan        # 期望 ~15Hz
```

日志在 `/tmp/px4_ws_lidar.log`，关键行：

```
Connection info:uartname /dev/ttyS4 baudrate 921600
```

后续正常起飞流程 `bash run.sh fly` 不用变。

### 实测结果（2026-10-09，`run.sh fly` 整条链路）

| 项 | 实测 |
| --- | --- |
| `/dev/ttyS4` | `crw-rw---- root dialout`，dmesg `ttyS4 at MMIO 0xfeb70000` |
| 串口握手 | `version: V4`；`LSRPM:900H OK`（900rpm = 15Hz）；`LSRES:300H NG`（该固件不支持，无害，重采样由驱动侧做） |
| `/scan` | **15.2 Hz，每帧 1200 点**（雷达原生 0.3° 分辨率） |
| `/tofsense/height` | 55.6 Hz |
| `/tracked_pose` | 30.1 Hz |
| `/fmu/in/vehicle_visual_odometry` | 15.0 Hz（EV 桥正常发飞控） |

> 结论：`carto_pkg / slam_pkg / px4_ev_bridge` 无需任何改动，串口雷达已完整顶替网口雷达。

> 注：`resample_res: 0.3` 会把重采样分辨率下发给雷达（`LSRES:300H`），这颗 LDS-50C-R
> 固件返回 `NG`；因为 `hard_resample: true`，驱动会在本机做 `resample()`，输出仍是
> 1200 点，功能不受影响。若想彻底消除这条 NG 日志，可把 `hard_resample/soft_resample`
> 和 `resample_res` 设成网口版那样（`false/false/-1.0`）。

## 5. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 日志 `COM_OPEN_ERR` / 打不开 `/dev/ttyS4` | overlay 没生效，回看第 3 步；确认重启过 |
| 日志 `device id [x] != my id [0]` 且无数据 | `uart_lidar.yaml` 把 `dev_id` 设成 `-1`（ANYONE），本仓库已是 `-1` |
| 有数据但全是 0 距离 / 乱点 | 波特率不对，试 230400 / 460800 / 921600；也确认下位机是不是 8N1 |
| 能出点但地图是镜像的 | `reversed` 抄错（网口版是 `true`，串口版应为 `false`） |
| `Permission denied` 开串口 | 用户不在 `dialout` 组：`sudo usermod -aG dialout orangepi` 后重新登录 |

## 6. 回退

```bash
sudo cp -a /etc/default/u-boot.bak-ttyS4 /etc/default/u-boot
sudo u-boot-update
sudo reboot
# 代码侧：LIDAR_PARAMS=~/px4_ws/src/bluesea2/src/bluesea-ros2/params/udp_lidar.yaml bash run.sh lidar
```

## 7. 附带修复：`microxrce-agent.service` 的串口默认值

`systemd/microxrce-agent.service` 里原本写着：

```ini
EnvironmentFile=-/etc/default/microxrce-agent   # 里面是 XRCE_DEV=/dev/ttyS6
Environment=XRCE_DEV=/dev/ttyS3                 # ← 后面这行把 ttyS6 顶掉了
```

`Environment=` 写在 `EnvironmentFile=` 之后，同名变量以它为准，于是 DDS Agent 会去开
**ttyS3**——而 ttyS3 是定高器 TOFsense-M 的口。该单元目前是 `disabled`（整条链路由
`px4-ev-chain.service` 拉起），所以还没炸，但只要有人 `systemctl enable` 它就会踩。

已改成：默认 `XRCE_DEV=/dev/ttyS6`，并把 `EnvironmentFile=` 挪到 `Environment=` 之后，
让 `/etc/default/microxrce-agent` 优先生效。同时在单元里注明：**本单元保持 disabled**，
避免和 `px4-ev-chain.service` 同时起两个 Agent 抢同一路串口。
