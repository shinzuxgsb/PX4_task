# D 题「立体货架盘点无人机系统」题目解析与实现思路

> 解析依据：`D题_立体货架盘点无人机系统.pdf`（2024 年全国大学生电子设计竞赛赛区赛
> 暨模拟电子系统设计专题赛初赛，本科组，共 5 页）。
> 文中所有尺寸均取自题图 1（仓库俯视图）与图 2（A 面正视图）。

---

## 0. 一句话概括

在一个 500cm×400cm、四周与顶部带安全网、无 GPS、光照不可控的场地里，
让一架**全自主**多旋翼在 **270s** 内对两个双面货架的 **24 个二维码**
（4 面×6 个）逐个完成"飞到位置 → 激光笔在码内点亮 0.5s → 识别编号 → 回传地面站"
的遍历盘点，并在 **180s** 内完成一次"看一张样码 → 规划航线 → 直飞该码 → 盘点 → 降落"的定向盘点。
核心矛盾是：**室内绝对定位精度**与**盘点速度**。

---

## 1. 任务拆解

系统 = 多旋翼飞行器 + 带 LCD 显示器的无线地面站。

| 分项 | 内容 | 关键动作 |
|---|---|---|
| 要求 1 | 遍历盘点 | 起飞 → 24 个码全部盘点 → 降落；地面站实时显示 |
| 要求 2 | 定向盘点 | 上电识别样码 → 上报编号 → LCD 显示规划航线 → 起飞飞到该码 → 盘点 → 回传 → 降落 |
| 要求 3 | 其他 | 5 分（创新点） |
| 设计报告 | 20 分 | 方案论证 3 + 理论计算 5 + 电路与程序 7 + 测试方案与结果 3 + 规范性 2 |

满分 120 分 = 要求 1（61）+ 要求 2（34）+ 要求 3（5）+ 设计报告（20）。
**注意：要求 1 是绝对大头，必须优先做稳。**

## 2. 评分点与硬性指标对照表

### 2.1 要求 1（61 分）

| 评分点 | 分值 | 量化指标 |
|---|---|---|
| 起飞点垂直起飞至 150±10cm | 5 | 高度误差 ≤10cm |
| 遍历盘点 24 个码 | 24 | 每码：激光笔在**二维码范围内**点亮一次，约 0.5s，且**成功收集一个货物信息** |
| 地面站实时显示 | 12 | LCD ≥3.5 吋；显示**货物编号（1~24）+ 位置坐标（A1~A6、B1~B6、C1~C6、D1~D6）**；每盘到一个货，LED 亮约 1s |
| 稳定降落在降落点 | 5 | 无人机几何中心不超出降落区域 |

| 遍历用时 | 10 | **越快越好** |
| **时限** | — | 起飞→降落连续完成，**270s 内**，超时相关模块不得分 |

### 2.2 要求 2（34 分）

| 评分点 | 分值 | 量化指标 |

| 飞往目标、打点、识别、回传、LED 闪烁 | 9 | 激光笔在码内亮约 0.5s；回传编号+坐标；LED 亮约 1s |
| 稳定降落在降落点 | 5 | 同上 |
| 定点盘点用时 | 10 | **越快越好** |
| **时限** | — | **180s 内**，超时相关模块不得分 |

### 2.3 全局硬性约束（违反即扣分或不予测试）

1. 轴距 **≤45cm**；桨叶**必须全防护**，否则不予测试。
2. 激光笔**水平向安装，不得移动、转动**；照射到板面的光斑直径 **≤6mm**。
3. 辅助定位方式**不限**（这是本题最大自由度）。
4. 起飞前可手动摆到起飞点、一键启动；**起飞后整个盘点过程不得人为干预、不得降落**。
   若用外部启动/急停装置，一键起飞后须立刻交给工作人员。
5. **每次测试全过程不得更换电池**；两次测试之间可换电池（≤2 分钟）。
6. 触地后能自行恢复飞行扣 5 分；触地 5s 内不能恢复判为失败（失败前完成的动作仍计分）。
7. 平稳降落 = 无明显跌落、弹跳、着地滑行。
8. 不得擅自改变测试环境条件 → **不能在地面/网上贴自制标记**。
9. 场地四周及顶部有安全网，网外测试现场避免阳光直射，但不排除顶部照明与窗外环境光；
   **不得对光照提要求**。

### 3.5 由几何反推出的四条"隐含结论"

**结论 1：激光笔水平安装 ⇒ 光斑高度 = 出光口高度，与水平距离无关。**
这是全题最容易被忽略、也最致命的一条。光斑高度完全由飞行高度决定，无法靠
飞远飞近来调整。

**结论 2：150±10cm 这个指标与 140cm 的关系是刻意设计的。**
上排码中心 140cm，码幅面下沿 130.5cm。150−10 = 140 恰好是上排码中心，
也就是说"**起飞爬到 150±10cm**"这个 5 分点是给上排码打点留的余量。
**若严格按 150cm 平飞，光斑落在 150cm，只比上排码上沿 149.5cm 高 0.5cm，几乎打不到码内。**

**结论 3：扫描上排与下排必须用两个不同高度。**
- 打上排：机体（激光出光口）高度取 **≈140cm**（可用范围 130.5~149.5cm）。
- 打下排：机体高度必须降到 **≈100cm**（可用范围 90.5~109.5cm）。
- 题目"至 150±10cm 的高度"是对**起飞动作**的把关，并非要求全程恒高；盘点阶段按行调高即可。
- **备选做法**：把激光笔固定在机腹/起落架下方，使出光口比机体基准低约 10cm，
  则机体在 150cm 时光斑正好落在 140cm，上排可用单高度完成；但下排仍需下降。
  两种理解建议赛前向裁判确认，并按"光斑必须落在 19cm 码幅面内"的严格口径设计。

**结论 4：相机与激光笔同轴（或共面、同向）安装，可以一举两得。**
由于光斑高度 = 出光口高度、且激光沿机体前向水平射出，只要把相机光轴调成与激光
**平行且尽量共线**，那么"相机画面里二维码居中"就等价于"激光光斑打在码中心"。
于是**视觉伺服对准**同时解决了"打得准"和"看得清"两个问题，且精度远超任何全局定位手段。
**强烈建议把这条作为整个方案的核心。**

### 3.6 可用通道（航线设计用）

- 西侧过道：x ∈ [0, 150)，A 面在此。
- 中间过道：x ∈ (150, 350)，B 面与 C 面相向而立，宽 200cm。
- 东侧过道：x ∈ (350, 500]，D 面在此。
- 南北横向通道：y ∈ [0, 100) 与 y ∈ (300, 400]，可横穿整个场地（货架只占 y∈[100,300]）。
- **货架高 190cm，而飞行高度只有 100~150cm，不能从货架上方跨越**，必须走通道绕行。
- 起飞点 (75,75) 在西侧过道南端；降落点 (425,325) 在东侧过道北端 —— 天然构成
  **从西向东、由南往北的单向扫掠**，非常利于规划高分数航线。

## 4. 关键技术难点

1. **室内绝对定位**：无 GPS、不能改造场地（不能贴标记）、光照不可控，
   却要精确飞到 24 个指定点。这是方案选择的胜负手。
2. **高频次精确对准**：24 个点要在 270s 内完成，平均每点仅约 11s（含飞行、稳定、打点、识别）。
3. **激光笔"打中"19cm 码**：水平安装、不可转动，光斑高度完全由高度决定，
   横向偏差必须控制在 ±9.5cm 以内。
4. **白色 PVC 板面 + 现场光照**：二维码是黑码白底贴在白板上，强光下对比度下降、
   有反光；需要补光或选高动态相机。
5. **全自主与续航**：一键起飞后完全无人干预，中途不得降落、不得换电池，
   单次任务要覆盖 270s 飞行 + 机载计算功耗。

## 5. 推荐总体方案

```
                        无线链路（WiFi / 数传）
     机载端  ──────────────────────────────────►  地面站
 ┌───────────────────────┐                    ┌──────────────────────┐
 │ 飞控 PX4 / ArduPilot  │                    │ 树莓派 / 笔记本       │
 │  ├ 定高：激光测距      │                    │  ├ ≥3.5吋 LCD（7吋触摸）│
 │  ├ 光流：PMW3901       │                    │  ├ 盘点结果列表 + 查询 │
 │  ├ 粗定位：UWB 标签     │                    │  ├ 航线图绘制         │
 │  └ 姿态/位置融合       │                    │  └ LED（GPIO，亮1s）  │
 │ 机载计算机（树莓派5）   │                    └──────────────────────┘
 │  ├ 前向相机（与激光同轴）│
 │  ├ 二维码识别           │
 │  ├ 视觉伺服对准         │
 │  └ 任务状态机           │
 │ 激光笔（固定、水平、可调校出光口高度）│
 └───────────────────────┘
```

**两条主线：**
- **粗定位（米级/十厘米级）** → 把无人机送到目标码前方 30~60cm 的机位附近；
- **精对准（厘米级）** → 相机看到码之后，用图像闭环把码推到画面中心，
  此时光斑必然落在码内，然后点亮激光、识别编号。

这个"粗定位 + 视觉伺服"的两级结构，把对全局定位精度的苛刻要求降到了很低的水平
（粗定位只需 ±15cm），是本方案能同时兼顾**精度**与**速度**的关键。

## 6. 分系统实现思路

### 6.1 飞行平台

| 项目 | 建议 | 理由 |
|---|---|---|
| 机架 | 轴距 350~400mm 四旋翼 + **全防护桨罩** | 满足 ≤45cm 且必须全防护 |
| 电池 | 4S 5000~6000mAh，悬停 ≥10min | 单次测试不得换电池，需覆盖 270s + 余量 |
| 飞控 | Pixhawk 6C / CUAV V5+ 跑 PX4 或 ArduPilot | 支持外部位置源接入、Offboard 控制 |
| 定高 | TFmini-S 激光测距 | 150cm 高度 + 100/140cm 分层，雷达比气压计稳得多 |
| 水平稳定 | PMW3901 光流 + IMU | 悬停抗漂移，视觉伺服期间的短时基准 |
| 机载计算 | 树莓派 5 / CM4（视觉重则可上 Jetson Orin Nano） | 跑识别 + 伺服 + 通信 |
| 相机 | 全局快门（OV9281）优于卷帘，或高动态 USB 相机 | 飞行+光照变化下不易果冻畸变 |
| 激光 | 650nm 激光模组，出光口高度可在装配时调校并锁死 | 光斑 ≤6mm，近距离自然满足；注意防晒眼 |

**装配要点：** 相机与激光笔装在同一个刚性支架上、同向朝前，出光口与相机光轴
尽量共线；装配后用"打点标定"测出光斑相对画面中心的固定偏差，写进代码做补偿。

### 6.2 定位与导航方案对比

| 方案 | 精度 | 依赖场地改造 | 光照影响 | 评价 |
|---|---|---|---|---|
| **UWB（4 基站 + 机载标签）** | 5~20cm | 基站自建，放场地边角 | 无 | **推荐做粗定位**，稳定、成熟、上手快 |
| **机载 2D 激光雷达 + 已知地图匹配** | 3~10cm | 无 | 无 | 精度好，但安全网是网面、反射弱，需实测 |
| **机载视觉里程计（VIO/光流）** | 漂移累积 | 无 | 依赖地面纹理 | 地面纹理差时不可靠，只能做辅助 |
| **外部俯视相机（装在安全网外俯拍）** | 1~3cm | 设备在网外 | 依赖光照 | 精度最高，但需与裁判确认是否允许 |
| **二维码地标定位** | 1~5cm | 无 | 中 | 24 个码本身就是已知坐标地标，可在扫描过程中自我校正 |

**推荐组合：** UWB 做全局粗定位 → 相机的二维码/视觉伺服做末端精对准；
光流 + 激光测距负责悬停稳定与定高；用已识别的二维码对位置做周期性重定位校正。

### 6.3 二维码识别

- 码内容是 **1~24 的数值**，标准 QR 码，幅面 19cm×19cm，识别难度不大。
- 库选型：**OpenCV `wechat_qrcode` 模块**（对偏色/模糊/反光最鲁棒）为首选；
  `quirc`（轻量、快，适合嵌入式）为备选；`ZXing-C++` 兼容性最好但稍慢。
- 相机与激光同轴时，只要光斑在码上，码就基本在画面中心 → 识别成功率天然很高。
- 建议加**主动补光**（小功率白光 LED 与相机同轴），并在算法中做
  自适应阈值 / CLAHE 增强，抵消白板强反光和顶部灯不均。
- 识别策略上做**多帧投票**：连续 2~3 帧解出同一编号才确认，防止误码。

### 6.4 激光指示与"打点"动作

一次合格的"打点"动作序列：

1. 无人机到达目标机位附近（粗定位 ±15cm 内）；
2. 相机锁定该码，视觉伺服把码中心推到画面中心（同时就是光斑位置）；
3. **保持姿态水平**（俯仰/横滚会同时让光斑和视线偏移）；
4. 激光开 → 保持约 0.5s → 关；
5. 同时完成二维码解码，确认编号；
6. 回传地面站 → LED 亮 1s。

**高度按行切换：** 打上排用 ≈140cm，打下排用 ≈100cm。
切换高度时用缓升缓降，避免超调导致光斑跑出码外。

### 6.5 航线规划

**要求 1（遍历）** —— 采用"西→东单向扫掠 + 面内之字形"：

```
起飞(75,75) → A面[6点] → B面[6点] → C面[6点] → D面[6点] → 降落(425,325)
```

- 4 个面的机位 x 依次为 110 / 190 / 310 / 390，天然单调递增，几乎无回头路。
- 面内顺序：上排 3 个（140cm）从左到右，再下排 3 个（100cm）从右到左，形成之字形。
- 面内横向移动仅 50cm、换行仅 40cm；面间最大移动约 200cm。
- 若希望进一步提速，可将面内 6 点顺序改为按同一列上下两点相邻（50cm 横移 → 40cm 升降 → …），
  减少高度切换次数。

**要求 2（定向）** —— 已知目标即已知坐标，直接做**避障最短路径**：

- 起飞点在 (75,75)，目标在任意面；若目标在 B/C/D 面，走 **y<100 或 y>300 的横向通道**
  横穿到目标所在过道，再纵向进入机位，**绝不能直线穿越货架板**。
- 到达后同样执行视觉伺服 + 打点 + 识别 + 回传，再飞往降落点 (425,325)。

### 6.6 地面站

| 功能 | 实现 |
|---|---|
| 硬件 | 树莓派 4B/5 + 7 吋 HDMI 触摸屏（满足 ≥3.5 吋） + 物理 LED（GPIO 驱动，串限流电阻） |
| 软件 | Python + PyQt/Tkinter，或本地 Web（Flask + 浏览器全屏显示）——**Web 方案出界面最快、最好看** |
| 实时显示 | 表格逐行追加：货物编号 / 坐标（A1~A6、B1~B6、C1~C6、D1~D6）/ 时间戳 |
| LED 闪烁 | 每收到一条盘点记录，GPIO 拉高 1s 后拉低（用独立线程，避免阻塞 UI） |
| 结果查询 | 输入框输入 1~24 → 立即显示对应坐标；也可用"已完成/未完成"高亮 |
| 航线图 | 用 matplotlib/PIL 预先画好场地底图（可直接复用本文档的 `tools/plot_arena.py`），
在要求 2 中把目标点与规划路径叠加显示 |
| 样码识别 | 要求 2 中，地面站显示"按一次键"，触发机载相机识别样码，随后显示编号 + 航线图 |

### 6.7 通信协议

数据量极小（每次几个字段），重点是**低延迟 + 不丢包**：

- 首选 **WiFi（UDP，带序号与重传）**：树莓派开 AP，地面站直连，延迟 <20ms。
  注意现场 2.4G 拥挤，建议固定信道并做丢包重传。
- 备用 **SiK 数传（433/915MHz）** 串口透传：带宽低但极稳，做兜底通道。
- 报文示例（JSON 或定长结构体）：

```json
{"type":"detect","id":13,"coord":"B1","ts":12.84}
{"type":"query","id":7}
{"type":"reply","id":7,"coord":"A5"}
{"type":"route","target":13,"path":[[75,75],[75,50],[190,50],[190,150]]}
```

- **心跳与状态上报**：地面站持续显示电量、高度、任务进度，便于调试与答辩演示。

## 7. 要求 1 执行流程与时间预算

状态机：

```
IDLE → 一键启动 → 垂直起飞至 150±10cm（把关点 5 分）
     → 从 (75,75) 飞往 A 面机位 (110, yn)
     → 对每个码：视觉伺服对中 → 激光亮 0.5s → 解码 → 回传 → LED 亮 1s
     → 高度切到 100cm 扫下排
     → B 面 (190) → C 面 (310) → D 面 (390)
     → 飞往降落点 (425,325) → 缓降稳定着陆 → 完成
```

时间预算（目标 120~150s，留足 270s 余量）：

| 环节 | 估计 |
|---|---|
| 起飞至 150cm | 5~8s |
| 24 点打点动作（伺服 0.5s + 激光 0.5s + 解码 0.2s + 稳定 0.3s） | ≈ 24 × 1.5s = 36s |
| 面内位移（约 24 × 0.5m + 高度切换） | ≈ 15s |
| 面间位移与绕行（4 段，共约 8m） | ≈ 25s |
| 降落 | 8~10s |
| **合计** | **≈ 90~100s** |

即便按 0.3m/s 的保守速度，也在 200s 内，**时序上是安全的**。

## 8. 要求 2 执行流程

```
① 上电，把抽取的二维码放在机载相机前 → 按一次键 → 机载识别出编号 N
② 查表得到 N 的绝对坐标与所在面 → 生成避障航线
③ 上报地面站：显示编号 N 与规划航线图（8 分）
④ 飞机摆到起飞点，一键起飞
⑤ 沿航线飞抵目标机位 → 视觉伺服对中 → 激光亮 0.5s → 解码校验
⑥ 回传编号 + 坐标 → 地面站显示 → LED 亮 1s
⑦ 飞往降落点 (425,325) → 稳定着陆
```

全程约 40~60s，远小于 180s 限制。

**注意第 ① 步的规则细节**："识别前仅可按键或者点击系统屏幕一次"——
识别动作必须由**一次**按键触发，不能反复按；代码里要做成单次触发 + 自动连拍识别。

## 9. 提速策略（两个 10 分项）

1. **缩小机位间距**：面内列间距只有 50cm，尽量用侧向平移（横滚/平移）而不是"减速-悬停-加速"
   的反复起停；用 S 型速度规划平滑过渡。
2. **连续式盘点**：到达机位前就开始识别，把"到位"与"识别"重叠，激光只在确认对中后触发。
3. **减少高度切换**：把 6 个点按"同高度相邻"排序，把 2 次高度切换压缩到每面 1 次。
4. **一次画面多码**：广角相机在 40cm 处可同时看到左右两列甚至三个列（列距 50cm），
   可作为**解码冗余与提前识别**，但激光仍需逐码打点。
5. **面间走大弧线**：面间长距离移动不要减到零速，用圆弧转场。
6. **整机轻量化**：减重直接提高机动余量，是提速的物理基础。

## 10. 风险与预案

| 风险 | 预案 |
|---|---|
| 光照不均导致二维码识别失败 | 主动补光 + 多帧投票 + 备用识别库 + 多次重试（重试时轻微移动机位） |
| UWB 多径导致定位跳变 | 加卡尔曼平滑；设置"定位野值拒绝"；以视觉伺服为末段唯一依据 |
| 光斑打不到码（高度/姿态偏差） | 赛前逐码标定出光口高度修正量；打点前强制水平姿态 |
| 撞到货架/安全网 | 设定软性禁飞区（货架板面 ±15cm 内、四周边界内缩 20cm） |
| 触地后不能恢复 | 设定最小安全高度保护 + 自主复飞逻辑；落地前减速缓冲 |
| 电池不足以覆盖整场测试 | 赛前实测"270s 任务 + 满负载计算"的耗电，留 ≥30% 余量 |
| 无线丢包 | 双通道（WiFi + 数传），关键报文重传 3 次 |

## 12. 赛前必须现场确认的清单

1. **B/C/D 面的编号方向**（1 号在 y=150 端还是 y=250 端）——直接影响要求 2。
2. 起飞点/降落点的尺寸标注是量到**边**还是**几何中心**（本文按图读为边与圆心）。
3. 安全网的高度和顶部净空，确认 150cm 以上是否有足够空间。
4. 激光笔"水平向安装"是否必须严格水平，还是允许固定俯角——决定采用单高度还是双高度方案。
5. 场地地面材质与纹理（决定光流是否可用）。
6. 现场 2.4G 频段拥挤程度（决定通信方案与信道）。
7. 是否允许在安全网外放置外部定位设备（UWB 基站、俯视相机）。
